## 功能状态

| 功能              | 当前状态 | 当前可用写法                 |
| ----------------- | -------- | ---------------------------- |
| 多风格提醒框      | 计划加入 | 普通引用，加明确的文字标题   |

## 多风格提醒框

提醒框用于集中呈现补充说明、操作建议和需要注意的事项。后续计划支持多种视觉风格；具体主题集合和切换方式尚未确定。

### 提醒内容如何组织

每个提醒应围绕一个具体事项，标题说明类型，正文说明原因或下一步。

| 类型示例 | 适合的内容                   |
| -------- | ---------------------------- |
| 说明     | 解释参数的默认行为           |
| 提示     | 提供更便捷的操作方法         |
| 重要     | 标出完成步骤所需的前提       |
| 警告     | 说明版本不兼容等已知问题     |
| 危险     | 说明删除或覆盖数据等操作后果 |

以上是内容分类建议，尚未定义为组件的参数值。

### 当前写法

现在可以用普通引用明确表达相同的信息。

**源码**

```md
> **重要：先填写必填信息**
>
> 每篇文章都需要 title、description 和 publish。
> 缺少必填字段时，内容校验会报告文件名和字段名。
```

**效果**

> **重要：先填写必填信息**
>
> 每篇文章都需要 title、description 和 publish。
> 缺少必填字段时，内容校验会报告文件名和字段名。

这一效果来自普通 Markdown 引用。提醒框组件的语法和主题配置将在功能接入后补充。

## 图片画廊与作品集

图片画廊适合把同一主题的多张图片放在一起浏览；作品集则需要在图片之外提供作品名称、说明和访问链接。

### 内容准备

准备图片时，建议同时整理以下信息，便于后续迁移到组件中：

- 图片地址：优先使用本站 `/images/` 下的资源。
- 替代文本：描述画面中的实际内容。
- 图注：补充图片背景、版本或拍摄信息。
- 作品名称与简介：说明作品是什么、用于什么场景。
- 访问地址：需要跳转到作品页面时填写。

### 当前写法

先用标准图片语法展示单张图片，再用正文补充图注和链接。

**源码**

```md
![文章从 Markdown 文件到页面的处理流程](/images/content-example.svg)

**作品名称：文章内容处理示意**

这张示意图说明 Markdown 文件经过内容解析后显示为文章页面的过程。

[阅读对应教程](/posts/engineering/markdown)
```

**效果**

![文章从 Markdown 文件到页面的处理流程](/images/content-example.svg)

**作品名称：文章内容处理示意**

这张示意图说明 Markdown 文件经过内容解析后显示为文章页面的过程。

目前连续插入多张图片会按正文顺序显示。网格排版、灯箱预览和作品卡片尚未提供；画廊接入后，本文会补充真实效果和配置示例。

## GitHub 仓库卡片

仓库卡片计划用于在文章中介绍开源项目，并提供直达仓库的入口。仓库信息如何获取、展示哪些字段、何时更新，将在组件实现时确定。

### 当前写法

普通链接现在即可使用，也可以配上与文章主题相关的介绍。

**源码**

```md
[nuxt/content](https://github.com/nuxt/content)

Nuxt Content 是本站读取 Markdown 和渲染 MDC 内容所使用的内容模块。
```

**效果**

[nuxt/content](https://github.com/nuxt/content)

Nuxt Content 是本站读取 Markdown 和渲染 MDC 内容所使用的内容模块。

这里没有请求 GitHub API，也不展示动态 Star 数、Fork 数或仓库状态。后续接入卡片后，会补充仓库标识写法、加载状态和请求失败时的效果。
